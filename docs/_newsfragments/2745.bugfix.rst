When a simulated ASGI request bubbled up an unhandled exception (as opposed
to an error rendered by an error handler), the test client's lifespan task
was left pending, and only reaped later by the garbage collector, emitting a
stray ``Task was destroyed but it is pending!`` warning. The same happened
when the body of an :class:`~falcon.testing.ASGIConductor` context raised.
Such orphaned lifespan tasks are now cancelled cleanly.
